# 产品需求

> 基于《AI Native 文档解析平台 · 系统设计文档 v1.0》产品需求章节整理

---

## 产品定位

AI Native 文档解析平台致力于为 Agent 和 RAG 知识库开发者提供多模态数据解析能力，将企业文档、图片、文本等多种格式转换为结构化的 Markdown / JSON 数据，为下游的知识库构建、智能检索和 Agent 应用提供高质量的数据底座。

## 目标客户

- **Agent / RAG 开发者** — 需要将各类非结构化文档解析为结构化数据，以构建知识库和 Agent 应用
- **企业决策者** — 希望通过企业级 Agent 降低运营成本、提升效率，需要可靠的数据解析平台作为基础设施

## 部署模式

私有化部署为主，以 Docker 容器化交付，支持单机 GPU 服务器运行。

## 核心业务范围

- 多模态数据摄入（文件上传 / 截图粘贴 / 文本粘贴）
- 文件类型识别（4 层级联管道）
- 多模态数据解析（文档解析管线 + 图片解析管线）
- 统一输出（Markdown / JSON）
- 任务管理与收藏管理

> 注：音频解析、视频解析属于预留扩展，当前不实现，但已定义接口协议。

## 三种摄入方式

| 方式 | 前端操作 | 后端接收 | 临时文件生成 |
|------|---------|---------|------------|
| 文件上传 | 选择文件 → 提交表单 | multipart/form-data | 直接存储原始文件 |
| 截图粘贴 | Win+Shift+S → Ctrl+V | `{ image_base64 }` | Base64 解码 → 临时图片文件 |
| 文本/代码粘贴 | 选类型（分段控件）→ 粘贴 → 提交 | `{ content, type_hint }` | 写入临时文本文件 |

> 文本/代码粘贴的 type_hint（text / code）仅为前端 UI 提示，后端独立识别，以后端判断为准。

## content_type 映射规则

| identified_type | content_type | 说明 |
|----------------|-------------|------|
| pdf / docx / pptx / xlsx / html / txt / md | file | 文档类统一归为"文件" |
| image / jpg / png / bmp | image | 纯图片 |
| image_formula / formula | formula | 含公式的图片 → "公式" |
| image_table / table | table | 含表格的图片 → "表格" |
| text | text_block | 粘贴普通文本 → "文本块" |
| code / python / javascript 等 | code | 粘贴代码 → "代码" |

## content_type 在 UI 中的呈现

用户在首页上传的内容类型，决定了它在收藏界面中出现在哪个 Tab：

| 首页上传 | 收藏 Tab |
|---------|---------|
| 上传 PDF/Word/PPT | [文件] Tab |
| 上传纯图片 | [图片] Tab |
| 上传含公式截图 | [公式] Tab |
| 上传含表格截图 | [表格] Tab |
| 粘贴普通文本 | [文本块] Tab |
| 粘贴代码 | [代码] Tab |
